# 文档生成规格（阶段 2-3）

## 阶段 2：制定 TODO LIST

在开始生成前，根据阶段 1 的扫描结果，输出待生成/更新的文档清单：

1. 列出所有需要生成或更新的文档（RULE.mdc + 5 个关系文档）
2. 对每个文档标注当前状态：`新建` / `需更新`（列出变更原因） / `已是最新`
3. 输出清单后立即开始执行阶段 3

---

## 阶段 3：文档生成

## 内容深度要求

生成的文档面向人和 AI 共同使用，信息宁多勿漏（读者可跳过冗余，但无法填补缺失）：

| 要求                       | 说明                                                               |
| -------------------------- | ------------------------------------------------------------------ |
| **表格列全量条目**         | 列出所有仓库/接口/依赖关系，禁止用"等"或"..."省略                  |
| **Mermaid 图覆盖全量节点** | 拓扑图、依赖图展示所有已知仓库和调用关系，不用示意性子集代替       |
| **关键信息附出处**         | 接口契约、变更影响等关键信息标注数据来源（哪个子仓库的 ai-readme） |
| **不确定则标注**           | 信息缺失时写 `<!-- TODO: 待补充 -->`，不省略整个章节               |

## 文件写入规范

**工具选择优先级**：

1. **优先使用 Write 工具** - 直接写入，无长度限制
2. **备用 Shell 命令** - Write 失败时使用

**目录写入优先级**：

1. **优先写入 `.cursor/rules/ai-readme/` 目录** - 默认首选
2. **如遇权限问题，降级写入 `.ai-readme/rules` 目录** - 完成所有文件写入任务后提示用户手动拷贝至 `.cursor/rules/ai-readme/` 目录
3. **如写入 `.ai-readme/rules` 仍失败，才使用 Shell 命令写入 `.ai-readme/rules` 目录**

## 核心原则：边生成边更新

**每生成一个文档，必须立即更新 `RULE.mdc` 快速导航表格中对应行的「状态」列！**

```
✅ 正确流程：
写入 项目群总览.mdc → 更新 RULE.mdc 状态列 [x] → 写入 系统拓扑.mdc → 更新 RULE.mdc 状态列 [x] → ...

❌ 错误流程：
写入所有文档 → 最后统一更新 RULE.mdc
```

## 断点续写机制

在 `RULE.mdc` 的快速导航表格「状态」列中维护进度，支持中断后继续：

```markdown
| 文档                           | 说明                       | 状态                    |
| ------------------------------ | -------------------------- | ----------------------- |
| [项目群总览](./项目群总览.mdc) | 项目群包含什么、各仓库职责 | [x] 2025-12-09 10:00:00 |
| [系统拓扑](./系统拓扑.mdc)     | 调用关系、数据流向         | [x] 2025-12-09 10:05:00 |
| [接口契约](./接口契约.mdc)     | 跨仓库接口定义、共享类型   | [ ]                     |
```

**状态规则**：

- `[ ]` 未完成 → 需要生成
- `[x]` 已完成 → 生成完成（追加时间戳）
- `[?]` 待确认 → 正在更新

## 文档格式要求

每个文档必须满足：

1. **Frontmatter**：description + alwaysApply: false
2. **至少 1 个图示**：Mermaid 关系图
3. **AI生成标记**：`<!-- AI生成，可根据团队规范更新 -->`

description 格式：`（简单概括）-（描述作用）；当 xxxx 时使用`

## 步骤 2.1：生成入口文件（RULE.mdc）

| 要素            | 说明                                                     |
| --------------- | -------------------------------------------------------- |
| **输出文件**    | `.cursor/rules/ai-readme/RULE.mdc`                       |
| **Frontmatter** | `alwaysApply: false`，description 必须包含"必读入口"字样 |
| **核心内容**    | 项目群总览、子仓库清单、快速导航（含状态列追踪进度）     |

**description 格式要求（强制）**：

```yaml
---
description: '多仓库项目群必读入口 - 项目群总览和导航；开始任何任务前必须先读取本文件，了解项目群上下文和仓库关系'
alwaysApply: false
---
```

**XML 标签结构化要求**：RULE.mdc 内容必须使用 XML 标签进行结构化，详见 [assets/rule-entry-template.md](../assets/rule-entry-template.md)。

**XML 标签说明**：

| 标签                 | 用途                | 模型行为                         |
| -------------------- | ------------------- | -------------------------------- |
| `<project_overview>` | 项目群简介          | 快速理解项目群定位               |
| `<generation_info>`  | 生成快照            | 追溯文档版本                     |
| `<repo_list>`        | 仓库清单和关系图    | 了解仓库间关系                   |
| `<quick_navigation>` | 文件导航 + 生成进度 | 按需跳转到具体文档，支持断点续写 |
