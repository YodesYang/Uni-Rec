# AGENTS.md 模板

> 参考 [agents.md](https://agents.md/) 最佳实践生成。
> AGENTS.md 是面向 AI coding agent 的项目指南，放置在项目根目录。

## 生成规则

| 要素         | 说明                                             |
| ------------ | ------------------------------------------------ |
| **输出文件** | 项目根目录 `AGENTS.md`（与 `package.json` 同级） |
| **生成时机** | 阶段 2 第一步，在 RULE.mdc 之前生成              |
| **数据来源** | 从 generated/ 文档中提取关键信息                 |
| **更新策略** | 每次执行都重新生成，无论是否已存在               |

## 章节规格

### 1. 项目概述

**数据来源**：`RULE.mdc` 的 `<project_overview>` 区块

**内容要求**：

- 一句话描述项目定位
- 核心能力列表（3-5 条）

**示例**：

```markdown
## 项目概述

基于 Monorepo 的规则分发系统，用于帮助团队统一管理和分发 AI 编程助手（Cursor/Copilot）的项目规则。

- CLI 工具：命令行方式安装和管理规则包
- VSCode 扩展：图形化界面管理规则
- 多语言规则包（Node.js、前端、Java、Go、PHP、Android）
- 团队协作：支持从远程 Git 仓库加载团队规则
```

### 2. 开发命令

**数据来源**：`generated/开发指南.mdc` 的环境准备和启动命令章节

**内容要求**：

- 依赖安装命令
- 开发服务器启动命令
- 测试运行命令
- 构建命令
- 仅列出实际可用的命令，不猜测

**示例**：

```markdown
## 开发命令

- 安装依赖：`pnpm install`
- 启动开发服务器：`pnpm dev`
- 运行测试：`pnpm test`
- 构建：`pnpm build`
- Lint：`pnpm lint`
```

### 3. 测试说明

**数据来源**：`generated/测试框架.mdc` 的测试工具和目录结构章节

**内容要求**：

- 测试框架名称
- 运行全量测试的命令
- 运行单个测试的命令（如果有）
- 测试目录结构说明
- 覆盖率要求（如果有配置）

**示例**：

```markdown
## 测试说明

- 测试框架：Vitest
- 运行全量测试：`pnpm test`
- 运行单个测试：`pnpm vitest run -t "<测试名称>"`
- 测试文件与源码同目录，位于各模块的 `__tests__/` 目录下
- 修改代码时需同步新增或更新对应测试
```

### 4. 技术栈简介

**数据来源**：`generated/技术架构.mdc` 的技术栈清单章节

**内容要求**：

- 语言/运行时版本
- 核心框架和库（3-6 条，只列关键依赖）
- 包管理器

**示例**：

```markdown
## 技术栈简介

- 语言：TypeScript 5.x / Node.js 20+
- 框架：NestJS、Commander.js
- 测试：Vitest
- 构建：tsup
- 包管理：pnpm（Monorepo）
```

### 5. 关键目录

**数据来源**：`generated/项目结构.mdc` 的目录树和模块清单章节

**内容要求**：

- 列出项目中最重要的 3-8 个目录及其职责
- 只列顶层或关键子目录，不展开完整目录树
- 每条说明控制在一句话以内

**示例**：

```markdown
## 关键目录

- `src/commands/` - CLI 命令定义和参数解析
- `src/services/` - 核心业务逻辑（规则解析、包管理、Git 操作）
- `src/templates/` - 规则模板和代码生成模板
- `packages/core/` - 共享核心库，供 CLI 和 VSCode 扩展复用
- `packages/vscode/` - VSCode 扩展源码
- `tests/` - 集成测试和端到端测试
```

### 6. 边界约束

**数据来源**：`generated/技术架构.mdc` 的设计约束章节 + `manual/边界定义.mdc`（如已存在）

**内容要求**：

- AI 在修改代码时应避免的行为
- 模块职责边界
- 技术选型约束（禁止引入的依赖类型等）

**示例**：

```markdown
## 边界约束

- 不要修改 `packages/core` 的公开 API，变更需先对齐接口设计
- 不要在 CLI 包中直接依赖 VSCode API
- 不要引入新的 HTTP 客户端库，统一使用已有的 `got`
- 不要在业务逻辑层直接读写文件系统，通过 `FileService` 抽象访问
```

### 7. AI 上下文

**内容要求**：

- 固定文本，指向 `.cursor/rules/ai-readme/RULE.mdc` 获取详细项目上下文

**示例**：

```markdown
## AI 上下文

详细的项目上下文（架构、核心流程、API 定义等）请参阅 `.cursor/rules/ai-readme/RULE.mdc`。
```

## 约束

- 使用中文撰写
- 保持精简，每个章节 3-8 行
- 仅包含从代码中可确认的信息，不猜测
- 禁止使用 Emoji 表情符号
