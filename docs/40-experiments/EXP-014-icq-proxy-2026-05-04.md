## 背景

在 `MultiSeqQueryGenerator` 中加入 DIN 风格的 target-item 感知：每个 sequence domain 学习一个 gate，将标准 global-info query 与 item-repr branch 进行混合：

```
gate_i  = σ(W_gate_i · [global_info_i, item_repr])   # (B, D)
q_{i,j} = (1 - gate_i) ⊙ FFN(global_info) + gate_i ⊙ FFN_item(item_repr)
```

`item_repr = mean(item_ns_tokens)`，`gate=0` 时退化为原始行为（backward compatible）。新增 +429,824 dense 参数（约 +17%）。

测试配置叠加 timefeat（EXP-012 已验证正向）一起跑，以 timefeat ON 为对照基线。

## Setup

- 数据：`/data_ams/industrial_training_data`
- 基础配置：`swiglu + rankmixer + valid_split_strategy=time + valid_ratio=0.05`
- proxy 窗口：`128/32 RG + 1500 steps + batch_size=128`
- `enable_time_of_day_features=True`（两组均开）
- `item_conditioned_query=True`（ICQ 组）vs `False`（对照）

## 结果

| Job | timefeat | ICQ | best val AUC | best val LogLoss |
|---|---|---|---|---|
| 对照（EXP-012） | ON | OFF | **0.839283** | **0.241525** |
| ICQ 本轮 | ON | ON | 0.837866 | 0.242013 |
| **Δ（ICQ vs 对照）** | — | — | **−0.001417** | +0.000488 |

## 结论

**ICQ 在 1500-step proxy 尺度是负向信号，不推进 full train。**

原因分析：
1. **参数量增加但 proxy steps 不足**：新增 430K dense 参数在 1500 steps 内未能充分收敛，gate 策略尚未学到有效值
2. **Gate 初始化噪声**：sigmoid 初始输出 ≈ 0.5，训练早期相当于同时向 base query 和 item branch 各注入 50% 未成熟的梯度，干扰了已稳定的 base query 路径
3. **item_repr 信号质量有限**：`mean(item_ns_tokens)` 在短训练后表征质量不足以给 gate 提供有意义的 item-specific steering

备注：ICQ 思路在 full train 尺度下（10 epoch，gate 有更多步骤学习）可能有收益，但 ROI 不确定，当前不冒险投入 full train 额度。代码已保留（`--item_conditioned_query` flag，默认 False），后期可视情况重启验证。
