This directly targets a gap in the accepted path-B implementation:

- Current accepted UE split only tokenises `user_dense_feats_61`.
- `user_dense_feats_87` is a 320-dim pre-normalized embedding, but current path keeps it in `other_dense` / dense_bypass.
- Current model has ICQ, DIN, dense_bypass, UE x user_int gating, and user_int x item_int DCN, but no explicit dense **UE x target item** interaction.

## Code Change

Added two opt-in switches:

| Switch | Meaning |
|---|---|
| `--ue_split_fids "61,87"` | Resolve multiple user_dense raw fids, concatenate their slices, and project them into the single existing UE token slot. Empty keeps legacy `--ue_split_fid 61`. |
| `--enable_ue_item_interaction` | Compute `UE`, `item_repr`, and `UE * item_repr`, project to `d_model`, and append as a classifier bypass. Requires `--enable_ue_split`. |

Implementation keeps the existing NS token count unchanged, so RankMixer's `d_model % T` constraint remains satisfied.
