## 目标

验证 hash embedding（`--seq_hash_vocab 500000`）是否能恢复 `domain_c_seq_47`（vocab=278M，被 `emb_skip_threshold=1M` 跳过 → 全零向量）丢失的信号，提升 AUC。

---

## 实验配置

**Job Name**：`t13-hash500k-timefeat-proxy-swiglu-vr005-rg128x32-s1500`

**关键 args**（在 timefeat 基线上叠加 T13 变更）：

```
--emb_skip_threshold 1000000
--seq_hash_vocab 500000
--enable_time_of_day_features
--limit_train_rgs 128 --limit_valid_rgs 32
--max_train_steps 1500
--valid_split_strategy time --valid_ratio 0.05
--seq_encoder_type swiglu
--batch_size 128
--num_epochs 4
```

**变更说明**：`--seq_hash_vocab 500000` 对超 vocab（>1M）的序列 item ID fid 启用 hash-mod 嵌入，降维到 500k 桶；原 `--emb_skip_threshold 1000000` 继续过滤非序列 id 超大特征。

## 分析

1. **Hash embedding 在 proxy 规模下明显负向（Δ−0.0016）**：与 timefeat-only 对照相比，AUC 下降超过 focal loss 的正向幅度，证明 500k hash 映射的收益低于其引入的 hash collision 噪声。

2. **可能原因**：
   - `domain_c_seq_47` 是序列中的 item ID（连续分布在 0~278M），hash-mod 500k 后高频热门 ID 被迫与长尾 ID 共享嵌入 → collision 干扰主信号
   - proxy scale 仅 128/32 RG + 1500 steps，hash embedding table 尚未充分预热；但相同规模下 timefeat 已经体现收益，说明问题不在于训练不足
   - `emb_skip_threshold=1M` 的跳过策略（全零）对当前 baseline AUC 影响有限，即对照本来已经丢弃该特征但表现更好

3. **切片诊断**：各桶 AUC 分布与 EXP-012 一致，没有特别退化的片段，说明是全局均匀下降而非某个分桶问题。

---

## 结论

- **Proxy 结论（2026-05-04 当时）**：hash500k 路线在 proxy 下 AUC **−0.001601**，低于 timefeat-only，不推进 full train。
- **保留代码**（`--seq_hash_vocab` flag 默认 0，不影响主线）。

## ⚠️ 2026-05-04 更新：Proxy 结论被 Full Train 推翻

用户独立启动了 **`t13tf-full-swiglu-vr005-bs128`**（`--seq_hash_vocab 500000 --enable_time_of_day_features`，full train），截至 E4/E4 其 best local AUC = **0.868178**，领先同期 `timefeat-full-swiglu-vr005-bs128`（timefeat-only）的 **0.867824**，Δ+0.000354。

**原因分析**：
- proxy 仅 1500 steps + 266k 行：hash embedding 500k 桶远未预热，collision 噪声淹没信号
- full train 1.9M 行 + 多 epoch：足够多样本让 hash table 学到有效表示，净收益转正
- **教训**：涉及大型 sparse embedding table 初始化/复位的变量，proxy 结果需打折扣，最好直接上 half-train（2~3 epoch）验证而非 proxy

**当前 T13 状态**：full train 候选，等待 `t13tf` 完成后按全局 best 评估。
