# 任务跟踪规范（Tasks · Meta-Spec）

> 本文件**只装规则与约定**，不装任务本身。任务正本：`active.md`（进行中）/ `archive.md`（已完成）。
> 任何对本文件的修改都属于「流程变更」，需在改完后同步更新 `active.md` 顶部「最近一次审视」一行说明。

---

## 文件分工

| 文件 | 职责 | 写入频率 |
|------|------|----------|
| `README.md`（本文件） | meta-spec：审视清单 / 状态约定 / 编号约定 | 极低（流程变更才动） |
| `active.md` | 进行中 `[~]` / 阻塞 `[!]` / 待启动 `[ ]` 任务 | 高（每个工作日可能动） |
| `archive.md` | 已完成 `[x]` 任务（精简一行 + 链到 EXP/ADR） | 中（任务完成时一次性追加） |

**单一事实源**：任何 task 的状态变更只在 `active.md` 落定。完成后 `[x]` 一次性搬到 `archive.md` 并加 `→ EXP-NNN` / `→ ADR-NNN` 链接。

---

## 状态约定

| 标记 | 含义 |
|------|------|
| `[x]` | 完成（搬到 `archive.md`） |
| `[~]` | 进行中（含可复用 recipe） |
| `[ ]` | 待启动 |
| `[!]` | 阻塞（须注明阻塞条件 + 解除条件） |

---

## 编号约定（三套独立编号体系）

| 前缀 | 含义 | 写入特征 | 示例 |
|------|------|----------|------|
| `T<N>` | Task | 频繁 status 变更，可关可重排 | `T8` 验证集按时间切 |
| `ADR-<NNN>` | Architecture Decision Record | **永不删，决策后只读** | `ADR-001` 选择 RG 级而非行级时间切 |
| `EXP-<NNN>` | Experiment | **结果只读**，一次 job 一个 | `EXP-002` 平台首次 baseline job |

**编号规则**：
- `T<N>`：从 1 开始连续编号；**不复用退役编号**（避免历史引用错位）
- `ADR-<NNN>`：3 位数字，从 001 开始；按决策时间顺序追加
- `EXP-<NNN>`：3 位数字，从 001 开始；按实验时间顺序追加

**何时升 ADR**：当一条 `[~]` task 涉及「为什么这么选 / 与备选方案的对比 / 反向风险评估」 → 推理写入 ADR，task 节点只留「→ 详见 ADR-NNN」。

**何时升 EXP**：当一条 task 跑出**可复现的数字**（AUC / Loss / 资源开销） → 数字落 EXP-NNN，task 节点只留「→ 详见 EXP-NNN」。

## 审视清单（每次接触 `active.md` 必跑 · 7 步）

按顺序执行。任何一步发现偏差 → 立刻动手修补，不留到「下次再说」。

1. **状态校验**：每条 `[~]` / `[!]` 状态是否仍准确？是否有暗中完成未打勾的工作？
2. **时间线压力**：对照 `docs/00-context/competition.md §2`（赛事时间表），距离最近 ddl 还有多少天？哪些 task 必须在此前推进？
3. **优先级重排**：高 ROI（杠杆大、阻塞少）的 task 是否排在前面？是否有「等结果型」task 可以并行启动？
4. **Recipe 时效**：每条 `[~]` 的 recipe 与当前 `baseline/` 代码、`schema.json`、依赖版本是否仍一致？
5. **红线复核**：执行路径是否仍满足 user rules 的四条红线？
   - 最小变更（不大改 baseline 文件）
   - 不新建 test 文件 / 文件夹
   - 生产安全（默认行为不变 / 配置开关 / 影响数据·采样·权重·特征的改动须给出验证方案）
   - 输出克制（无废弃 helper / debug 文件）
6. **下一步具象化**：对每条 `[~]` / `[ ]`，写一句「未来 30 分钟可做的最小动作」。写不出 → 拆分、合并或降级为 `[ ]`。
7. **沉淀回写**：在 `active.md` 顶部「最近一次审视」**覆盖**写最新结论（**不累积**，老的进 changelog）；任何状态变更须在对应 task 节点附 inline 注释 `(YYYY-MM-DD: ...)`。

**输出规范**：审视结论用结构化表格 / 列表呈现，不要埋在散文段落里。

## 反模式（禁止）

- ❌ 用户问「TODO 进展如何」时，跳过 `active.md` 直接凭印象回答
- ❌ 改 task 状态但忘记 bump「最近一次审视」与 `Changelog`
- ❌ 新增 task 不分配稳定的 `T<N>` 编号；或复用已退役编号
- ❌ 把 6 步以上审视结论塞进段落散文，而不是表格 / 列表
- ❌ 在 chat 里口头说「已完成 T<N>」却不更新 `active.md`
- ❌ 完成的 task `[x]` 留在 `active.md` 不归档（污染审视开销）
- ❌ 把决策推理写在 task inline 而不升 ADR；把实验数字写在 task inline 而不升 EXP
